# Real-server validation: extended (V1, R-VAL-2)

Template for a human to fill in against a real Plex server, the real plex.tv and, for the Pi rows, real Raspberry Pi hardware. Every parameter, flag and command the spec marked (verify) is listed. Only `Overall: PASS` closes the `real-server-validation-extended` phase (D11). A FAIL names the phase to reopen.

**Secrets rule: never paste a token or a full `X-Plex-Token` URL into this file.** Check any pasted Diagnostics text or command output and delete any token or URL that carries one.

Result values: PASS | FAIL (<phase to reopen>) | SKIPPED (<reason>, extended Pi rows only)

How to fill in: replace the placeholder after each `Result:` with PASS or FAIL, write what you saw after `Notes:`, then replace the last line with `Overall: PASS` once every row is PASS (or SKIPPED where allowed). Only rows marked `skip if no Pi` may be SKIPPED, and the reason goes in Notes. Use `curl -H "X-Plex-Token: $(cat /dev/fd/3)" ... 3<tokenfile` style requests, never a token on the command line or in a URL, when you query Plex by hand.

Run note (2026-10-14): run by the conductor at the owner's request ("run the extended checklist for me", D50), on HOME with the installed Microsoft Edge 155 (headless, playwright-core 1.56.1) and the app from commit 61316e2 served by `scripts/serve.mjs`. The owner approved the sign-in codes, gave the token-rotation facts and did V1-E24 on a phone. Rows that need a device off the network or a blocked address use a block inside the browser and say so.
